# 請求モードのクイックリファレンス

ユーザー完了とモデル別使用量の請求モードを選択するための簡単な比較ガイド。

## 簡単な比較

|特集 |ユーザーによる入力完了 |モデル別の使用法 |
|-------|-------|----------------|
| **デフォルトモード** | ✅ はい | ❌ いいえ |
| **コスト構造** |固定 (ライセンス割り当て) |変数 (トークンごと) |
| **ユーザー権限** |不要 |有効にする必要があります |
| **コスト追跡** |完了数 |トークン数 + コスト |
| **最適な用途** |予測可能なコスト |大容量使用 |
| **フォールバック サポート** | ✅ はい | ❌ いいえ |

## 各モードをいつ使用するか

### ユーザー完了モード

**次の場合にこれを選択してください:**
- ✅ 予測可能な固定費が必要です
- ✅ 既存のライセンス制限内にあります
- ✅ 内部ツールを構築しています
- ✅ 既存のクォータ割り当てを使用したい場合
- ✅ シンプルなコスト管理が必要です

**使用例の例:**
- 社内チャットボット
- 開発とテスト
- 少量のアプリケーション
- 固定予算プロジェクト

### モデルモード別の使用法

**次の場合にこれを選択してください:**
- ✅ 詳細なコスト追跡が必要です
- ✅ 高価なモデルを頻繁に使用している
- ✅ 実際の使用量に対してのみ支払いたい
- ✅ 詳細な使用状況分析が必要です
- ✅ 大量の要件がある

**使用例の例:**
- 実稼働アプリケーション
- 大容量 AI サービス
- コスト重視のプロジェクト
- マルチモデルアプリケーション

## API の使用法

外部 API を課金モードで使用する場合:

```bash
curl -X POST "https://{customer.name}.hiperai.ai/api/external/chat/completions" \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-nano",
    "prompt": "Hello, world!",
    "user_id": "optional-user-id-for-billing"
  }'
```

## レート制限

### デフォルトのレート制限
- **1 分あたりのリクエスト数**: 60 (構成可能)
- **1 時間あたりのリクエスト**: 1,000 (構成可能)
- **1 日の制限**: 100 リクエスト (構成可能)
- **月間制限**: 10,000 リクエスト (構成可能)

### 請求モード固有の制限
- **ユーザーの完了数**: ライセンス割り当てに基づく
- **モデルごとの使用量**: ドルベースの追加制限

## SMLTP ポリシーの統合

どちらの課金モードでも、SMLTP ポリシーの適用がサポートされています。

|ポリシー |説明 |使用例 |
|----------|---------------|----------|
| `public` |機密性のないデータの場合 |公開アプリケーション |
| `internal` |会社データについて |内部ツールとプロセス |
| `confidential` |機密情報について |アクセス制限付きアプリケーション |

### SMLTP 構成例

```json
{
  "billingMode": "usage-by-model",
  "allowedSMLTPPolicies": ["public", "internal"],
  "enforceSMLTPPolicies": true,
  "allowedModels": ["openai/gpt-5-nano", "anthropic/claude-sonnet-4.6"]
}
```

## 構成例

### ユーザー入力の構成

```json
{
  "billingMode": "user-completions",
  "dailyLimit": 100,
  "monthlyLimit": 1000,
  "allowedModels": ["openai/gpt-5-nano", "anthropic/claude-sonnet-4.6"],
  "allowedSMLTPPolicies": ["public", "internal"],
  "rateLimit": {
    "requestsPerMinute": 60,
    "requestsPerHour": 1000
  }
}
```

### モデル構成別の使用法

```json
{
  "billingMode": "usage-by-model",
  "dailyLimit": 500,
  "monthlyLimit": 5000,
  "allowedModels": ["openai/gpt-5-nano", "anthropic/claude-sonnet-4.6"],
  "allowedSMLTPPolicies": ["public", "internal", "confidential"],
  "rateLimit": {
    "requestsPerMinute": 120,
    "requestsPerHour": 2000
  },
  "usageByModel": {
    "enabled": true,
    "dollarLimit": 100.00
  }
}
```

## エラーのシナリオ

### ユーザー入力エラー

|エラー |原因 |ソリューション |
|------|------|----------|
| `Completion limit exceeded` |毎月の割り当てに達しました |モデルごとの使用を有効にするか、クォータを増やす |
| `Daily limit exceeded` | 1 日の制限に達しました |リセットするか制限を増やすまで待ち​​ます |
| `User not found` |無効なユーザー ID |ユーザーが存在することを確認する |

### モデル別の使用法エラー

|エラー |原因 |ソリューション |
|------|------|----------|
| `Usage by Model required` |ユーザーはそれを有効にしていません |ユーザーのモデルごとの使用を有効にする |
| `Usage by Model budget exceeded` |毎月の予算に達しました |ドル制限を引き上げる |
| `Invalid billing mode` |無効なモードが指定されました | `"usage-by-model"` または `"user-completions"` を使用します。

## 移行ガイド

### ユーザーの入力からモデル別の使用まで

1. **ユーザーに対してモデルごとの使用を有効にする**
   ```bash
   # Admin panel: Users > Edit User > Enable Usage by Model
   ```

2. **API キー構成を更新します**
   ```json
   {
     "billingMode": "usage-by-model",
     "usageByModel": {
       "enabled": true,
       "dollarLimit": 100.00
     }
   }
   ```

3. **使用状況とコストを監視する**
   - トークンの使用状況を追跡する
   - 毎月の支出を監視する
   - 必要に応じて制限を調整します

### モデル別の使用法からユーザーによる完了まで

1. **ユーザーに十分な割り当てがあることを確認します**
   - ライセンス層を確認する
   - 毎月の制限を確認する

2. **API キー構成を更新します**
   ```json
   {
     "billingMode": "user-completions",
     "dailyLimit": 100,
     "monthlyLimit": 1000
   }
   ```

3. **完了の使用状況の監視**
   - 完了カウントの追跡
   - フォールバック動作が機能することを確認する

## コストの見積もり

### ユーザー完了コスト

- **固定コスト**: ライセンスレベルに基づきます
- **追加料金なし**: 既存のライセンスを超えて
- **予測可能**: Web インターフェイスの使用法と同じ

### モデルコスト別の使用量

- **変動コスト**: トークンの使用量に基づきます
- **モデル固有の価格**: モデルごとに異なる料金
- **費用の例**:
  - GPT-5.1: プロバイダー料金が適用されます
  - Claude Sonnet 4.6: プロバイダー料金が適用されます
  - GPT-5 Nano: プロバイダー料金が適用されます

## モニタリングのヒント

### ユーザー完了の監視

- 毎日の完了カウントを追跡します
- クォータの消費を監視する
- 限界に近づいた場合のアラートを設定する
- 使用パターンを毎月確認します

### モデル監視による使用状況

- トークンの使用量とコストを追跡する
- 毎月の支出を監視する
- ドル制限アラートを設定する
- モデルごとのコストの内訳を確認する

## セキュリティに関する考慮事項

### 両方のモード

- 機密性の高いアプリには IP 制限を使用する
- API キーを定期的にローテーションする
- 異常なアクティビティを監視する
- 適切なエラー処理を実装する

### モデル別の使用法

- 適切な金額制限を設定する
- コストの高騰を監視する
- モデルの使用パターンを確認する
- 高価なモデルの使用状況を追跡する
